### Visual Hierarchy

The modal is read left-to-right: the inputs column is the user's workspace, and the right results panel is the payoff surface.

1. **Primary anchor:** the right-panel **"Total to repay"** value rendered at **20 px GeistMono SemiBold** (Display role). This is the single number the user opened the modal to see.
2. **Secondary anchor:** the left inputs column, led by the **Collateral** `BtcInput` and **Amount taken** `FiatInput`.
3. **Tertiary anchors:** the interest/fees breakdown rows and the liquidation-price / APR rows below the total.
4. **Conversion basis label** uses the Accent brush so it reads as live, context-aware metadata without competing with the total.

## Interaction Contract

1. **Live recalculation.** Every observable input property change triggers a `Recalculate()` method. The ViewModel builds a `BtcLoanSimulationInput` and calls `BtcLoanSimulationCalculator.Calculate` from Phase 44. No submit button is required.
2. **Currency effects.** Changing the currency selector updates the `CurrencySymbol` on the `FiatInput` controls, reformats the existing amount/fee values, and recomputes the sat values and conversion basis using `RatesState`.
3. **Sats hiding.** If `RatesState.BitcoinPrice` is null or zero, all sat result `TextBlock`s have `IsVisible="False"` and the conversion-basis label shows the fallback copy (see Copywriting Contract).
4. **Invalid inputs.** Non-parseable or non-positive collateral/principal, an end date on or before the start date, or an out-of-range LTV silently clear the results to the empty state ("---"). No error toast is shown in Phase 45.
5. **Interest mode toggle.** Simple/Compound toggle works like the Long/Short toggle in the Leverage Simulator: one button is always checked, checked state uses the accent style.
6. **Prefill slot.** The prefill `ComboBox` is present with one placeholder option. Selecting it does nothing. Phase 47 will populate it with real BTC-backed loans and wire prefill logic.
7. **No persistence.** The modal is ephemeral. Closing it does not write to the database, matching the Leverage Simulator behavior.
