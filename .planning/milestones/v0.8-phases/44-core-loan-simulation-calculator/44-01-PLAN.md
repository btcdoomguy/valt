    Extend the calculator to cover the remaining success criteria.

    1. Compound-interest path:
       - Daily `decimal` loop over `days = EndDate - StartDate`. For each day `i` from `1` to `days`:
         - `dailyInterest = runningPrincipal * input.Apr / 365` (unrounded).
         - Add `dailyInterest` to a running `accruedInterest` total.
         - Add `dailyInterest` to `runningPrincipal` so the next day compounds on the updated balance (fees are excluded from the balance).
       - `Interest = Math.Round(accruedInterest, 2)`; `TotalRepay = Principal + Interest + Fees`.
       - This is the documented daily compounding frequency for SIM-04.
    2. Monthly schedule for compound mode:
       - Walk the same daily loop, but emit a `LoanScheduleEntry` on each month-end anchor plus the final `EndDate`.
       - If `StartDate` is itself a month-end, still emit the first anchor on that date (it is also the first row). If `EndDate` is a month-end, the closing row replaces the duplicate month-end anchor so the schedule ends exactly on `EndDate`.
       - At each anchor, store `AccruedInterest` = running accrued interest up to that date, and `CumulativeTotal = Principal + AccruedInterest + Fees`.
       - The final row must use the same rounded `Interest` and `TotalRepay` so the final `CumulativeTotal` equals the headline total.
    3. Effective APR:
       - If `days <= 0` or `principal <= 0`, return `0`.
       - `totalCost = TotalRepay - Principal`.
       - `effectiveApr = Math.Round(totalCost / Principal * 365m / days, 2)`.
       - For compound mode, this uses the actual total repayment produced by the daily loop (D-06).
    4. Liquidation price:
       - `collateralBtc = input.CollateralSats / 100_000_000m`.
       - `liquidationPrice = TotalRepay / (collateralBtc * input.LiquidationLtv / 100m)`.
       - Round to 2 dp for display parity.
       - If `collateralBtc == 0` or `LiquidationLtv == 0`, return `0`.
    5. Add the following test methods to `BtcLoanSimulationCalculatorTests`:
       - Compound-mode happy-path: 90-day loan at 12% APR, assert total repay is greater than the simple-mode total for the same inputs (compounding must produce a strictly higher interest when days > 1).
       - Schedule-equality test: assert the final row's `CumulativeTotal` equals `TotalRepay` for both simple and compound modes.
       - Effective APR test: assert the effective APR for a known simple loan equals the nominal APR when fees are zero (e.g., 30 days, 12% APR, no fees → effective APR ≈ 12.00%).
       - Liquidation price test: known inputs where `TotalRepay = 25_000`, `CollateralSats = 100_000_000`, `LiquidationLtv = 80` → expected `25_000 / (1 * 0.8) = 31_250`.
  </action>
