    Per the 51-CONTEXT.md MCP Tool Contract decision: add a single read-only tool `GetGoalContributingTransactions(IQueryDispatcher dispatcher, [Description("ID of the goal (from GetGoals)")] string goalId)` decorated `[McpServerTool, Description("Get the transactions contributing to a goal's progress, with running total")]`. Follow the GetGoal pattern (lines 40-46) exactly: dispatchers injected as method parameters, no notification publish.

    Tool logic, in order:
    1. Dispatch `new GetGoalQuery { GoalId = goalId }`; if the goal is null, return null (GetGoal not-found convention — do not throw, do not return an error string).
    2. Dispatch `new GetGoalContributingTransactionsQuery { GoalId = goalId }`. If `result.IsFailure`, return null.
    3. Map to a new MCP-owned DTO `GoalContributingTransactionsMcpResult` (declare it in this tool file, per AGENTS.md — do not reuse App DTOs as the return shape). Fields: `bool Supported`, `string? GoalType`, `string? StrategyUnit`, `decimal? FinalTotal`, `IReadOnlyList&lt;GoalContributingTransactionMcpRow&gt; Rows`.
    4. When the App result is `GoalContributingTransactionsResult.NotSupported`: return `new GoalContributingTransactionsMcpResult { Supported = false, GoalType = "NetWorthBtc", StrategyUnit = null, FinalTotal = null, Rows = [] }` — typed, not an error.
    5. When `Supported`: map each `ContributingTransactionRow` to `GoalContributingTransactionMcpRow` with fields `Date` (DateOnly), `Description`, `Account`, `Category` (string?, null when uncategorized), `FiatAmount` (decimal, `row.FiatAmount.Value` — magnitude, non-negative), `FiatCurrencyCode`, `SatsAmount` (long, `row.SatsAmount.Sats` — magnitude), `Contribution` (decimal, the running-total delta: first row = its RunningTotal, subsequent rows = this row's RunningTotal minus the previous row's RunningTotal — the App row type carries only RunningTotal, so Contribution is derived), `RunningTotal` (decimal). Set `Supported = true`, `FinalTotal = rows[^1].RunningTotal`.
    6. `GoalType` = the `GoalTypeNames` enum name for `goal.GoalType.TypeId` (cast `(GoalTypeNames)goal.GoalType.TypeId`, add `using Valt.Core.Modules.Goals;`).
    7. `StrategyUnit` = one of "Fiat", "Sats", "Count", "Percentage" replicating the `SummaryStrategyUnit` semantics in src/Valt.UI/Views/Main/Tabs/Transactions/Models/GoalEntryViewModel.cs lines 204-211: TypeId 0 (StackBitcoin), 4 (IncomeBtc), 6 (BitcoinHodl) → "Sats"; 2 (Dca) → "Count"; 8 (SavingsRate) → "Percentage"; all others → "Fiat". Implement as a private static helper mapping on TypeId (do not reference the UI-layer enum from Infra).
    8. Add one using line: `using Valt.App.Modules.Goals.Queries.GetGoal;` and `using Valt.App.Modules.Goals.Queries.GetGoalContributingTransactions;` (GetGoal query already imported? — verify; add only what's missing).

    Declare both DTOs as `public sealed record` with `required` init properties at the bottom of the tool file, mirroring how other tool files keep MCP DTOs colocated. XML-doc the DTO fields tersely.
