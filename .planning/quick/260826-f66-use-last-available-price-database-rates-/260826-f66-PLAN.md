# Quick Task 260826-f66: Use last available price database rates at startup

**Description:** Use last available price database rates at startup and merge live API rates to prevent KeyNotFoundException in AccountsTotalState.

## Goal

Ensure `RatesState` is always seeded with the latest stored rates from the price database before the app tries to calculate totals, and that live API responses are merged with those stored rates rather than replacing them. This prevents `KeyNotFoundException` when the main currency or an account currency is missing from an incomplete/offline live price update.

## must_haves

- `RatesState` is populated from the price database immediately after the price DB is opened during startup.
- `LivePricesUpdaterJob` merges live API rates with stored rates; missing currencies keep their last stored value.
- `AccountsTotalState.CalculateCurrentWealth` never throws `KeyNotFoundException`; it safely handles missing rates.
- Existing tests still pass; new tests cover incomplete/offline live price responses and missing-currency wealth calculation.

## Tasks

### 1. Create `IPriceDatabaseRatesProvider` helper

**Files:**
- `src/Valt.Infra/Crawlers/LivePriceCrawlers/PriceDatabaseRatesProvider.cs` (new)
- `src/Valt.Infra/Crawlers/LivePriceCrawlers/IPriceDatabaseRatesProvider.cs` (new)
- `src/Valt.Infra/Extensions.cs`

**Action:**
- Define an interface `IPriceDatabaseRatesProvider` with a method to get the latest BTC price and a dictionary of the latest fiat rate per configured currency from the price database.
- Implement it using `IPriceDatabase` and `IConfigurationManager.GetAvailableFiatCurrencies()`.
  - For BTC: use the most recent `BitcoinDataEntity` price.
  - For each configured fiat currency: use the most recent `FiatDataEntity` price for that currency (look back a few days, e.g. last 7 days, to handle weekends/holidays).
  - Return a `BtcPrice` and a `FiatUsdPrice` with `UpToDate = false`.
- Register the service in `Valt.Infra` DI.

**Verify:**
- Build succeeds.
- Unit test: when price DB contains BTC and BRL entries, the provider returns both.

### 2. Seed `RatesState` from the price database at startup

**Files:**
- `src/Valt.UI/Services/DatabaseLifecycleService.cs`

**Action:**
- After `_priceDatabase.OpenDatabase()` in `InitializePriceDatabaseAsync`, before triggering `LivePricesUpdater`, call `IPriceDatabaseRatesProvider.GetLatestRatesAsync()` and publish a `LivePriceUpdateMessage` via `INotificationPublisher`.
- The message must have `IsUpToDate = false` so `LiveRateState` correctly shows offline/stale.
- Wrap in try/catch and log; startup should never fail because of seeding.

**Verify:**
- Integration test: after `InitializePriceDatabaseAsync`, `RatesState` contains rates for all configured currencies even when live providers are mocked to fail.

### 3. Merge live API rates with stored rates in `LivePricesUpdaterJob`

**Files:**
- `src/Valt.Infra/Crawlers/LivePriceCrawlers/LivePricesUpdaterJob.cs`

**Action:**
- At the start of `RunAsync`, load the latest stored rates via `IPriceDatabaseRatesProvider` and publish them as the baseline (same as step 2, but also inside the job so every run starts fresh).
- After a successful API call, build the final rate dictionary by starting from the stored rates and overlaying the values returned by the API.
- For each configured currency, if the API did not return it, keep the stored value.
- For BTC, if the API did not return a USD price, keep the stored BTC price.
- `isUpToDate` should be `true` only when both providers report up-to-date **and** all configured currencies are present in the API response.
- Remove the old `LastKnownPricesAsync` path or reimplement it to use the same helper.

**Verify:**
- Existing test `Should_Get_LastKnownPrices_And_Send_Message` still passes.
- New test: API returns only USD/EUR while DB has BRL → published message includes BRL from DB.
- New test: API returns all configured currencies → published message is fully up-to-date.
