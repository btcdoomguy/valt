<objective>
Fix the bug where pasting a numeric value into any FiatInput currency field (e.g. Update Loan State > Current Interest Paid) registers as 0 while typing works.

Purpose: The shared FiatInput user control intercepts TextInputEvent (tunnel) and assumes e.Text is a single digit char. A paste raises the same event with the full clipboard string ("1.234,56"), which fails the `char.IsDigit(e.Text[0])` gate when it starts with a separator/symbol, or throws via `long.Parse(e.Text)` on a decimal string — and `e.Handled = true` unconditionally swallows the paste either way. Result: value stays 0 everywhere FiatInput is used (73 usages across modals).
Output: A patched OnTextInput in FiatInput.axaml.cs that parses multi-character paste text as a culture-aware decimal and updates `_rawValue`, while preserving single-char typing behavior.
</objective>
