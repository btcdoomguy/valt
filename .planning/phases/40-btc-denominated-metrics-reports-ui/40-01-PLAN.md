## Assumptions carried forward from the spec-less probe

Because the phase entered plan-phase without a SPEC.md, the three BTC requirements were unresolved by the probe. The following scope assumptions are now explicit and are implemented in this plan:

1. BTC purchases and sales are excluded from "sats earned" and "sats spent" but are included in "stack velocity" (D-01, D-09).
2. Transactions whose transaction date has no exact BTC price in the price database are silently skipped; no UI warning or drill-down is shown (D-06, D-07).
3. The current incomplete month is included in the monthly earned/spent/velocity trend, with no special "in progress" styling (D-03, D-12).

## Other cross-cutting declarations

- API coverage: This phase does not introduce a new external API/SDK/webhook/plugin. No COVERAGE.md matrix is produced.
- Schema push: No ORM schema push is required; Valt uses LiteDB with DTO mappings. No migration is needed for read-only metrics.
- Assumption-delta: No singular→plural / required→optional / derived→chosen transition is introduced. The phase adds new read-only DTOs derived from existing aggregates and rates.

## Trust Boundaries

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-40-01 | Tampering | Filter date ranges / account IDs in `GetBtcDenominatedMetricsQuery` | low | mitigate | Ranges are bounded by `DateCalendarSelector` (Year/All modes); account/category IDs are validated against `provider.Accounts`/`provider.Categories` in the query. |
| T-40-02 | Denial of Service | Large date ranges or many transactions in `BtcDenominatedMetricsQueries` | low | mitigate | Use the cached `IReportDataProvider` and a single-pass in-memory aggregation; no blocking I/O inside the loop. |
| T-40-03 | Information Disclosure | Stack velocity reveals BTC trade direction | low | accept | The user already owns the data; the metric is intentionally user-visible. |
| T-40-SC | Tampering | NuGet/package installs | n/a | n/a | No new packages are installed in this phase. |
